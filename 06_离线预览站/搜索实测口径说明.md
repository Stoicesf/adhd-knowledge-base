# 预览站本地检索模拟（非真实 BookStack 站内搜索）

## 四项声明

### 1. 测量环境

- 本轮**无真实 BookStack 实例**；测量在 `F:\ADHD文献\06_离线预览站\` 完成。
- 运行环境（实数）：
  - **Node v22.23.2**：用于 eval 内嵌 JS、跑 DOM stub、触发 `doSearch()`。
  - **Python 3.13.16**：用于重新生成 `index.html` 与产出 `搜索实测结果.csv`。
  - 浏览器侧：本轮未用 Edge 截图；如后续补截图，再补 Edge 版本号。
- 检索实现 = **本地子串匹配**（不是分词、不是全文索引）。

### 2. 分词口径

- 预览站匹配逻辑：`q.toLowerCase().indexOf(keyword.toLowerCase()) !== -1`，去首尾空格；子串命中即算命中。
- 真实 BookStack 使用 **ICU 分词与全文索引**（分词边界、停用词、词干还原、排名打分）。
- 两者**行为不会完全一致**；本地结果只能作近似证据。

### 3. 结论措辞

- 本文件与相关报告只允许写：**"本地模拟近似通过"**。
- 禁止出现："实测通过""已验证通过""已证明"等定性表述。

### 4. `0/10` 的效力边界

- `0/10`（壳页在预览前 10 条结果里占 0 条）只是**近似证据**，不能作为真实检索行为的证据。
- 真实数据写入"部署后验收清单"，等有 BookStack 实例再补。
- **分母是实际返回条数，不是 10**：本轮实测为 0/8（药物）、0/3（剂量），另有两个查询返回 0 条（副作用、要不要吃药）。不足 10 条的原因见 §1——本地索引仅 19 个内容页、不含壳页。巡检照表核对时，`0/8` 不是"漏测两条"，`无结果` 也不是"没触发横幅"（横幅照常触发）。

## 为什么 CSV 纯数据、声明性文字放本文件

`搜索实测结果.csv` 要保持首行即列头，以便 Excel / 表格工具直接打开；如果在第 1 行前加标题行，会破坏列头对齐、下游引用断链。因此：

- CSV 侧：只放数据，列头不动；
- 声明侧：本文件写四项声明、观察项、口径说明；
- 双向引用：本文件 → `搜索实测结果.csv`；`预览说明.md` → 本文件。

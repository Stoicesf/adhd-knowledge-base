### 候选句排除表（24 句按语义归类，逐类给排除理由）

| 类别 | 代表句（逐字） | 排除理由 |
|---|---|---|
| 回避二次伤害 / 延后追问 | 「话术只解决当下这一句，**不翻旧账、不预测明天**」「复盘点等状态回来之后再定，**不在当晚追问原因**」「按情绪先处理，**不追问原因**」 | **方向相反**：修复需要家长主动承认刚才失态并重新连接，这些句子要求「不提、不追问」，属发火后的克制纪律，不是修复动作 |
| 任务复盘的时点安排 | 「**第二天复盘点**也写在同一个位置：『明晚先看第一行』」「留一个**第二天再说**的小记号」 | 复盘对象是**今晚的作业任务**，不是亲子关系；且是「何时再谈任务」的安排 |
| 当下降温 / 回到题目 | 「把本子合上，说一句：『先不急，我们把**刚才卡住的那题**看一眼就好』」「等他呼吸平了，只问一句…」 | 「刚才」指**卡住的题目**，不是家长刚才发火；动作目标是让孩子回到题目，属当下降温 |
| 向专业方陈述 | 「再按来源边界去联系有处方权的医生…**把情况按时间顺序说清楚**」 | 对象是医生/心理老师，属安全事件路由，不是亲子关系修复 |

### 清单外发现（本轮最有价值的一条）：`router.route()` 并没有场景白名单

方案 Q2 写「确认 `router.route()` 只查辅导场景，不查 `parent_escalation`」，字面不成立：

- `router.py:98-100` 的 `in_scope` 是 `rec.audience in allowed and (scenario is None or rec.scenario == scenario)`
  —— **没有辅导场景白名单**，只有「调用方传什么就收窄到什么」；
- 实测 `route(state, "parent", "parent_escalation", skills=[], chunks=…)` → `retrieve` 注入 **2 条 `pc_*`**；
- 实测 `route(state, "parent", None, skills=[], chunks=…)` → 注入 **11 条，其中 `pc_*`=2 + `fes_*`=3**，
  即 **`scenario=None` 时家长急救块会串进辅导检索**（默认态，skills=[] 只为强制走检索通道以暴露行为）。

**当前不干扰的真实原因（三层，缺一不可）**：
1. `build.retrieve()` (`build.py:250/252`) 有 `audience !=` / `scenario !=` 两道 `continue` **硬过滤**，
   服务侧 `server.py:110` 传的是硬编码 `("parent","parent_escalation",…)`；
2. `server.py` **不 import router**（实测 `import router` 不存在），`handle_parent_escalation` 只调
   `retrieve` + `judge`（`server.py:98` 签名、`:110/:117` 调用）；
3. `regression.py` v1.3 的 `entry_via` 守卫把 6 条旁路轨迹摘出 `router.route()`，
   并断言「非旁路轨迹却使用 `parent_escalation`」为失败。

即：**隔离靠「调用方传参 + 旁路守卫」，不靠 `router` 自身过滤**。`scenario=None` 是一个
真实存在的串扰入口，只是当前 25 条走 router 的轨迹都传了具体辅导 scenario，未触发。
本批次按边界「不碰编译管线行为」**不改 router、不加断言**，如实记为残余风险（见 §残余边界）。

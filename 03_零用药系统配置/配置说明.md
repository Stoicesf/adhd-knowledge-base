# 零用药系统配置 · 部署配置说明（运维照做版）

> 本目录交付的是"零用药"系统级配置实物，本轮不部署、不装 Docker。以下步骤在你的 BookStack 实例后台上完成；菜单名随版本可能不同，**以你所装版本后台为准**，拿不准处先在后台搜索设置项名称。
> 站点域名当前全部为占位域名 `https://wiki.example.org`（待替换）。部署后第一步就是跑 `python 设置域名.py https://你的真实域名`，再做后续验证。

## 〇、规模与两条腿分工（先读这一段再动手）

本轮已完成**壳页收敛**，最终规模三层：

- **词表 111 条全保留**（`药物关键词表\药物关键词表.json` / `.csv`）：40 个主词条 + 71 个常见变体，全部用于搜索页横幅匹配，一个词都不删。
- **药品名壳页 18 条**（`重定向页\` 下 18 个 `.md`）：9 个商品名（专注达/專注達/择思达/擇思達/利他林/利他靈/阿德拉/阿得拉/Adderall）+ 5 个分子名（哌甲酯/盐酸哌甲酯/鹽酸哌甲酯/托莫西汀/托莫西丁）+ 4 个其他通用名（可乐定/可樂定/氯压定/胍法辛）。每个壳页正文只有一行 `#REDIRECT` 指向兜底页。
- **无壳页词条 93 条**：通用词（药/药物/剂量/副作用/要不要吃药/停药/换药……）与错字/繁简变体一律不建独立页面，命中后**只由横幅兜底**提示，不进入站内搜索结果索引。

**两条腿的分工**：

1. **药品名精确命中 → 走壳页**。用户搜"专注达""择思达"等 18 个药品名之一时，BookStack 直接命中对应 `.md` 壳页，壳页一行 `#REDIRECT` 跳到兜底页 `medication-boundary`，URL 与标题都干净。
2. **通用词与问句 → 只由横幅兜底**。用户搜"药物""剂量""副作用""要不要吃药"等 93 个通用词时，站内不会再撞出任何壳页（这些词没有页面），只在搜索结果页顶部横幅出现统一的"本库不提供用药建议"提示，并附"查看本库边界说明 →"链接跳兜底页。

> 之前一版曾给全部 111 条词各建一张壳页，导致搜"药物"时同屏挤出 6–9 张跳转壳、稀释检索。本轮已删除 93 张通用词壳页，只留 18 张药品名壳页，检索稀释问题已大幅缓解。

## ① 把横幅片段粘进 BookStack 的 Custom HTML Head Content

1. 用**管理员账号**登录后台。
2. 进入系统设置：**Settings → Customization（自定义）**，找到 **Custom HTML Head Content（自定义 HTML Head 内容）** 输入框（具体菜单名以你所装版本后台为准；不同版本在 Settings 下的位置可能是 "Customization" 或 "Features"）。
3. 用文本编辑器打开 `搜索页横幅注入片段.html`，**全文复制**，粘贴进该输入框，保存。
4. 保存后：**强制清一次浏览器缓存并重新登录**（Custom HTML Head 属于 head 级注入，旧缓存可能不刷新；如站点开了服务端缓存/视图缓存，按后台提示或重启 php-fpm/容器后再验证）。
5. 验证：站内搜索"剂量"，结果列表最上方应出现横幅，可点关闭，不遮挡搜索框，手机宽度下不横向溢出。

> 横幅内联了完整的 111 条词条数组（与 `药物关键词表.json` 的 pages 集合一致），这是 93 条无壳页词条的唯一拦截入口。**不要**因为壳页只剩 18 张就去精简横幅词表——横幅一缩，通用词搜索就漏拦。

## ② 创建 18 个药品名壳页

**仅为 18 个药品名各建一条独立页面**，标题 = 该词原文（如"专注达""择思达""哌甲酯"），正文**只有一行**：

```
#REDIRECT [https://你的真实域名/books/public-kb/page/medication-boundary] 
```

（方括号后必须保留一个空格；不得加标题、正文、元数据块。）共 **18 页**，与 `重定向页保留清单.csv` 行数一一对应。其余 93 个词条**不建页**。

**路径 A · 后台手工**（仅适合挑几个补页）：
1. 进入书籍 A（slug `public-kb`）→ 章节"边界说明"。
2. 逐页新建：标题填 `重定向页保留清单.csv` 的 `词条` 列，正文粘贴 `重定向页\` 下对应 `.md` 文件里的那一行，保存。

**路径 B · API 脚本批量建**（推荐，18 页走这条）：
1. 在 BookStack 后台 **Settings → API 令牌**（Settings → API）建一个有"创建页面"权限的令牌。
2. 用 API 调 `POST /api/pages`，`book_id` 取书籍 A 的 ID，`chapter_id` 取"边界说明"章节 ID，逐行读 `重定向页保留清单.csv`：`name` = `词条` 列，`markdown` = `重定向页\<文件名>` 文件内容，`slug` 可强制指定为 CSV 的 `redirect_page_slug` 列（不强制则由 BookStack 生成）。CSV 为 UTF-8 带 BOM，Python 用 `utf-8-sig` 读。
3. 文件名安全化规则已落定（见 `重定向页保留清单.csv` 的 `文件名` 列）；导入时按文件名一一对应即可。

> 不要照 `药物关键词表.csv` 的 111 行去建 111 个页——那里 93 行是 `has_redirect=False` 的通用词条，只用于横幅匹配，**没有也不应有**对应壳页。

## ③ 壳页的目录可见性与权限

1. **不进入任何导航**：18 个药品名壳页全部挂在"边界说明"章节下、集中存放，不在首页/书籍首页/导航树单独列出；首页（A00）只保留一个入口指向兜底页本身。
2. **仅内容管理员可编辑**：在 BookStack 角色权限中，把"边界说明"章节（或这些页面）的编辑/删除权限只授给内容管理员角色；C 端贡献者与 B 端编辑角色对这些页面**只读或无权**。
3. 页面本身**不设证据状态、不进审核评分表**——它们只是跳转壳。

## ④ 验证方法（实测口径）

1. **通用词应 0 壳页命中**：站内分别搜"药物""剂量""副作用""要不要吃药""停药"——结果列表里**不应出现任何跳转壳页**，只应在顶部看到横幅；不得出现任何展开讲药物的正文页。
2. **药品名应落兜底页**：站内搜"专注达""择思达""利他林""哌甲酯"——应命中对应壳页并立刻跳转到兜底页 `medication-boundary`，同时横幅仍在。
3. 搜一个错字/变体（如"專注達""擇思達""阿得拉"）：横幅应命中（横幅脚本做了不区分大小写 + 去空格匹配）；其中属于 18 个药品名清单的会跳壳页，其余只出横幅。
4. 直接访问某个药品名壳页（如 `/books/public-kb/page/med-zhuanzhuda`）：应跳转到兜底页。
5. 点页面底部反馈区块的"这是一个用药问题"：应跳到兜底页，不在站内展开药物回答。
6. 不命中时确认无横幅：搜一个普通词（如"写作业"），页面顶部不应出现横幅。

## ⑤ 改域名后要重新验证哪几项

1. 重跑 `python 设置域名.py --check` 应为 0 处改动（幂等确认）。
2. 重新打开任意药品名壳页（抽几个，如 `专注达.md`、`Adderall.md` 对应的页）：跳转目标是新域名而非 `wiki.example.org`；改域名必须重跑 `python 设置域名.py <真实域名>`（18 个壳页每个都含一处占位 URL），跑完后按 ④ 的搜索与跳转步骤回归一遍。
3. 横幅里的"查看本库边界说明 →"链接指向新域名。
4. 反馈区块"这是一个用药问题"链接指向新域名。
5. 浏览器强刷后再做一遍 ④ 的搜索验证（横幅是 head 注入，改域名后片段已变，需清缓存）。

## 已知代价与后续收敛选项（写给运维的备注）

**当前实现的代价**：壳页收敛后只剩 **18 张药品名壳页**（9 商品名 + 5 分子名 + 4 其他通用名）。这 18 张壳页彼此**互不为近义词**——它们各自对应一个具体药名，搜"药物/剂量/副作用"这类通用词时不会撞出任何一张壳页，之前"搜'药物'同屏挤 6–9 张跳转壳"的检索稀释问题已大幅缓解。

**两条错字壳页已删**：`哌甲脂.md`、`盐酸哌甲脂.md` 是"哌甲酯/盐酸哌甲酯"的常见错写。这两条词条**仍保留在 111 条词表里**（`has_redirect=false`），横幅会按变体照样命中；只是不再作为独立页面进入搜索结果索引，避免错写词也产生一张跳转壳。

**后续收敛选项（观察项，暂不执行）**：当前 18 张壳页本身仍会进入搜索索引。未来若观察到"搜某个商品名时，除壳页外还想完全去掉壳页、纯靠横幅命中"，可再考虑是否把商品名类壳页也进一步收敛掉（即 9 个商品名壳页是否也改为横幅兜底）。**这是商品名类是否还要进一步收敛的观察项**，不是通用词收敛——通用词已经收敛完毕、当前没有通用词壳页可删。若要执行，顺序仍须是：先确认横幅对该商品名的全部变体（含繁简、英文）都能命中，再删对应壳页，避免"页删了、横幅没拦住"的空窗。

这一节是运维备注，不是对当前实现的否定；当前版本保持"18 药品名壳页 + 111 条词条横幅兜底"。
